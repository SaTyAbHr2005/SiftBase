# Task worksheet implementation

This iteration implements the query-time worksheet path in the existing synthesis mode. It keeps Qwen thinking disabled and GLM 5.3 Flash as the independent judge. It does not claim an accuracy gain until the fresh development benchmark is scored.

- The existing planning call proposes query-anchored operations and required source roles. Code validates literal anchors, operation types, IDs and bounds; missing tasks get generic query-derived defaults. Source-role searches get independent retrieval/triage queues. Acronym hints come only from definitions in retrieved source text and remain alternatives.
- All verified writer-visible spans are eligible. The fact inventory suggests candidates; it no longer vetoes findings. Worksheet writers do not have mandatory fact restoration or a second generic appraisal writer. Legacy taskless fixtures retain their source-copy fallback for compatibility.
- The same writer call returns linked source inputs and operation outcomes. Code resolves document/page/section/offsets, copies exact quotes, and checks source-owned entity/metric/period/unit/basis values. Missing scope stays unknown. Mismatched scope is incomparable; numeric comparisons with unresolved scope fail before the semantic checker. A deliberate varying field must be requested in the literal query anchor.
- Final verification independently checks claim support and whether the requested operation was performed. Faithful but nonresponsive summaries cannot establish completion. Worksheet/coverage details stay inside existing traces/artifacts and response coverage.
- Factual screening accepts relevant explanations, counterevidence and qualifications without treating their incidental numbers as answers. An initial tranche and reserve can be followed by at most two recovery batches from already retrieved candidates, prioritizing possible explanatory source language. Every retained fragment still passes model verification. A verified direct value stops recovery; explanations alone do not. Existing call, byte, deadline and monetary admission limits still apply. There is no unlimited rescan or arbitrary context fallback.
- Explanatory factoids use checked synthesis instead of clipping evidence down to a numeric clause. Public coverage includes verified, remaining, budget-omitted and recovery counts; partial inspection never proves document-wide absence.
- A checker may identify a query-relevant source core behind an unsupported *finding phrase*. At most four exact-source cores receive one additional semantic-check call. Wrong scopes, background, unsupported premises, interpretations and gaps are ineligible. Failed/budget-denied repair never retries or auto-approves a copied quote. Structured original verdict reasons and repair counts remain visible.

Scope limits: no global graph, new database, retriever training, visual interpretation, or model/thinking switch. Recovery consumes existing promising candidates; there is no additional dynamic external retrieval loop. Query-time scope alignment is conservative and may leave useful but underspecified comparisons unresolved. The two requested cases are development cases already inspected during diagnosis; the combined iteration is not a causal ablation of each component.

Offline regressions cover advisory selection, semantic rejection, negative evidence, bounded recovery/stopping, immutable provenance, scope mismatch/unknowns, deterministic calculation guards, operation completion and one-call repair. Existing route, trace, source-isolation, citation and budget regressions remain required. Fresh C32/C26 results will be recorded separately with the measured commit and complete costs.

The first live pass exposed a scheduling defect: the planner could legitimately take longer than the fixed cumulative 16.5-second verification cutoff, so C26 admitted no evidence checks. Verification now uses the *remaining* 30-second early-stage deadline; the actual deadline, token/call caps and final-stage grace are preserved. An offline clock regression covers both admission after slow planning and denial after actual expiry. The initial pass is preserved, and one corrective pass carries its full prior cost into the same aggregate $0.10 ledger.

The follow-up iteration removes LLM-driven next-batch selection. Analytical candidates return to the deterministic, ranked and task-fair batch path, whose calls run concurrently within the existing deadline and token/call ceilings. A 12-fragment batch experiment verified fewer C26 source fragments and scored worse than the prior 8-fragment run, so the batch size remains 8. The ranked path is being rechecked against C32/C26 after removing the selector; no accuracy gain is assumed.

## Bounded task coverage and example continuation

The latest code gives each explicit analytical task one first candidate slot, then returns to the ranked aspect queue before considering the remaining task-role candidates. If verification is cut off by a budget denial, one deterministic verifier-only recovery tranche is selected from the denied candidates for tasks whose verified evidence count is still below their operation-specific minimum. Verification tags evidence with task IDs and reports per-task counts/statuses. It adds no planner or batch-selector call; normal request, token, deadline and monetary gates still apply. Taskless analytical queries retain their existing conclusion-first ordering.

For source passages that explicitly mark an example as illustrative, retrieval follows at most two adjacent pages in the same section and retains only passages matching query or task vocabulary, with an eight-element cap per seed. This is intended to keep an example's values near its caveat while preserving the caveat's meaning. An offline check against the saved FDIC index now includes the page-32 allowance table through this source-declared continuation; the page-31 qualification remains independently retrievable. This check is not a live C32 benchmark.

The first full C26 pass with every task-role queue placed ahead of the aspect queue regressed to **23.53% / 11.11% / 92.31% / 37.50%** (answer precision / answer recall / context precision / context recall), 104.84 seconds, and 13 returned chunks. It verified 24 of 179 candidate fragments. That scheduling order was narrowed so only one candidate per task precedes the ranked aspect queue. The subsequent C26 attempt used the remaining cumulative generation allowance, stopped after 9 fragments, and could not admit its writer call; its **0% / 0% / 60% / 9.38%** scores are budget-truncated and are not a valid quality comparison. No further live call was made because the carried-forward $0.07 generation cap was nearly exhausted.

The previous completed static C26 run remains the better measurement: **80.00% / 34.21% / 100.00% / 90.62%**, 106.34 seconds, 29 returned chunks, and 72 of 179 fragments verified. Therefore the current changes are regression-tested but the refined task-first ordering has not yet earned an accuracy claim. Focused offline suites pass **191 tests** (one slow test deselected). The official evaluator remains unchanged. Raw benchmark inputs, responses and cumulative ledgers are in ignored local artifact folders `artifacts/task_fair_recovery_c26_20261024/` and `artifacts/task_fair_recovery_c26_refined_20261024/`.

## Pick writer (opt-in)

`KB_ANALYTICAL_WRITER=pick` replaces the worksheet writer's free-text statements with sentences taken from the sources. It uses the same plan tasks and the same fact inventory as the worksheet writer. The default is still `synthesis`.

- The inventoried facts are split into sentences and table rows. A table row keeps its header, and a sentence whose fact carries context from the sentence before (such as "It took 2 milliseconds ...") keeps that sentence, so the subject is not lost. A sentence that a longer one already contains is dropped. Abbreviations such as "U.S.", "e.g." and "Ltd." do not end a sentence.
- The sentences are grouped under their document's file name, so the model can tell one paper's terms from another's. One `answer` call returns, for each task, the IDs of the sentences that answer it, most direct first. Each task gets at most its share of the worksheet's statement budget, and unknown IDs are ignored.
- Each picked sentence becomes a statement word for word, with its citation. A sentence picked for two tasks is shown once and counts for both. The claim check makes no model call for these statements, since their text is the source's.
- Headings are the short phrases the question itself uses for each task (one to four words). They are printed only when there are at least two tasks and every task has its own phrase; otherwise the answer has no headings. The planner's task sentence is never printed, because it can restate a premise of the question that no picked sentence confirms.
- If the call fails or picks nothing usable, the worksheet writer runs as before. A task with no picked sentence stays unresolved and is listed as a limitation.

Measured on the 8-question set (2 runs each, same judge): the pick writer before the heading rule scored 49.3% / 35.1% and 44.6% / 33.4% answer precision / recall, with median query times of 14 s and 20 s. Rebuilding both runs' answers from the same picked sentences with the heading rule gave a mean of 52.1% / 34.0%. The default writer's two runs on `8e38a2e` average 63.7% / 31.3%. The pick writer also used fewer Cloudflare neurons per run: 1,370 to 1,786, against about 2,600. Known weak spots: on A21 it picked auditor boilerplate and scored zero in both runs, and table rows can come out as raw cells.
